Runs

What is this?

Every training you run produces a run: a folder on disk recording the exact settings, the random seed, and the results — so any number can be traced back and reproduced. This table lists them all. final eval is the score when the trained agent was tested (average ± spread over 20 test episodes with exploration turned off). steps is how many environment interactions the training used — its budget. Tick checkboxes to plot, watch, or compare runs.

Learning curves

What is this?

A learning curve shows the agent getting better (or not) during training: score on the vertical axis, training progress on the horizontal. A rising curve means it's learning; a flat one means it's stuck; a jagged one is normal — reinforcement learning is noisy. Use the metric dropdown to switch what's plotted; the explanation of the chosen metric appears below the chart.

Agent view

What is this?

This plays a fresh test episode with the trained agent and draws it live — you're watching the actual decisions the neural network makes at every step, not a recording of training. A well-trained CartPole agent keeps the pole up the whole time; a barely-trained one drops it in seconds. Comparing the two is the clearest picture of what training changed.

Tick one run above, then watch the trained agent act. Greedy policy, fresh evaluation episode.

Comparison

What is this?

One training run proves little — luck (the seed) matters a lot in RL. The honest workflow is: run the same setup with several different seeds, then compare the group statistically. IQM is a robust average (it ignores the most extreme quarter of results on each side). The 95% CI is the uncertainty range: "the true typical score is probably in here." Wide interval = too few runs to be sure. The yellow warnings below results are the platform telling you when your comparison isn't yet trustworthy — take them seriously, that honesty is the whole point of this lab.

Select runs above and press “Compare selected”. Groups are (algorithm, environment); scores are recorded final evaluation returns; intervals are bootstrap CIs from rlcore.stats with a fixed seed.

Launch a run

What is this?

Pick an algorithm, optionally change settings, press Launch — a real training process starts on this machine. A description of the chosen algorithm appears below the dropdown. The important fields: seed (change it to repeat the same experiment with different luck — that's how you build a fair comparison), the budget field (updates or total_steps: more = better but slower), and env_id (which task). Everything else has sensible defaults shown in grey.

Empty fields use the config default shown as placeholder. Values are parsed as JSON (numbers, true/false, lists) or kept as strings. Runs land under the server's launch root with a full standard run directory.

Research ideas — questions you can answer here

What is this?

Real, answerable research questions this lab supports out of the box. Each one names something to vary and something to measure. Click Set up in launch form to pre-fill the settings, press Launch, repeat with seeds 0–2 (change only the seed field between launches), do the same for the other variant if the idea has one, then tick the runs and Compare selected. That loop — vary one thing, hold everything else fixed, repeat across seeds, compare honestly — is the scientific method, and it's the entire point of this platform.
